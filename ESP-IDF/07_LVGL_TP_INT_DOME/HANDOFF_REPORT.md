# HXESP3636AI0210QIC-A 功能模块开发交接报告

更新时间：2026-08-24  
主要目标：梳理并验证各 ESP-IDF 功能示例，当前重点为将 `06_LVGL_Test` 的触摸驱动从 FT3168 替换为 CST3530。

## 1. 项目与硬件概况

- 主控：ESP32-S3。
- 板载 Flash：16 MB。
- 板载 PSRAM：8 MB Octal PSRAM。
- 原理图位置：`F:\softwork_2.0\HXESP3636AI0210QIC-A\原理图`。
- 当前使用的公共 I2C 总线：SCL=GPIO14，SDA=GPIO15。
- ESP-IDF：v5.5.4。

## 2. 已处理模块

### 2.1 `01_ADC_Test`

- 已给 `components/adc_bsp/adc_bsp.c/.h` 补充关键中文注释。

- ESP-IDF 5.5.4 会提示旧版 `driver/i2c.h` 已弃用，目前不影响运行，未来可迁移到 `driver/i2c_master.h`。

- 曾出现 GCC 14.2.0 编译 ESP-IDF 自带 `esp_lcd_panel_rgb.c` 时的内部编译器崩溃；这不是 Wi-Fi 源码语法错误。

## 3. 当前重点：`06_LVGL_Test` CST3530 触摸移植

- `components/esp_touch/touch_bsp.c`
- `components/esp_touch/touch_bsp.h`

当前 `touch_bsp.c` 只保留了头文件和：

说明 CST3530 移植尚未实现，`touch_Init()` 和 `getTouch()` 当前没有函数定义。

`touch_bsp.h` 仍保留原接口：

```c

```

其中“初始化 FT3168”的旧注释需要在实现时改为 CST3530。

I2C BSP 当前已经使用：

```text

SDA = GPIO15
```

已有 I2C 接口只直接支持单字节寄存器地址；CST3530 使用4字节命令/寄存器地址，因此不能直接沿用原 FT3168 的 `I2C_read_buff(addr, reg, ...)`。可以复用通用写后读接口，或增加专用的4字节地址读写接口。

### 3.3 已确认的 CST3530 协议参数

| 项目 | 已确认数据 |
|---|---|
| 正常7位I2C地址 | `0x58` |
| Boot地址 | `0x5A` |
| SDA/SCL | GPIO15/GPIO14 |
| RESET | GPIO40，低有效 |
| INT | GPIO11，低有效，输入上拉 |
| 建议复位时序 | RESET低10 ms，拉高后等待50 ms |
| 芯片信息地址 | `0xD0030000` |
| 信息读取长度 | 50字节 |
| CST3530芯片类型 | `0xCACA220E` |
| 触摸报告地址 | `0xD0070000` |
| 首次读取长度 | 9字节（4字节帧头+首个5字节项目） |
| 后续项目长度 | 每个5字节 |
| 最大报告项目 | 5（触点数+虚拟按键数） |
| 读点结束ACK | `D0 00 02 AB` |
| 坐标报告类型 | `0xFF` |
| 手势报告类型 | `0xF0` |
| 接近感应类型 | `0xE0` |

### 3.4 触摸报告帧格式

- `frame[0..1]`：16位校验值，低字节在前。
- `frame[2]`：报告类型。
- `frame[3]`低4位：触摸点数。
- `frame[3]`高4位：虚拟按键数。
- 从 `frame[4]` 开始，每个触点或按键占5字节。

每个触点的数据格式：

| 偏移 | 含义 |
|---:|---|
| 0 | X低8位 |
| 1 | Y低8位 |
| 2 | 压力值 |
| 3低4位 | X高4位 |
| 3高4位 | Y高4位 |
| 4低4位 | 触点ID |
| 4高4位 | 触摸事件 |

坐标组合关系：

```text
X = byte0 | ((byte3 & 0x0F) << 8)
Y = byte1 | ((byte3 & 0xF0) << 4)
```

事件解释：

- `event == 0`：抬起。
- `event != 0`：有效按下或持续接触。
- 现有参考驱动没有明确区分首次按下与移动的具体非零编码。

帧校验算法：

```text
checksum = 0x55 + 所有项目数据字节之和
```

校验范围从 `frame[4]` 开始，长度为 `(触点数 + 按键数) × 5`。

### 3.5 芯片信息区字段

- 芯片类型：`buf[0..3]`，小端组合，期望 `0xCACA220E`。
- X分辨率：`buf[28] | (buf[29] << 8)`。
- Y分辨率：`buf[30] | (buf[31] << 8)`。
- 坐标字段为12位，理论表达范围0～4095；实际有效范围以信息区返回的分辨率为准。

### 3.6 普通初始化要求

普通点屏不需要下载大型配置表，也不需要移植40 KB固件升级逻辑。最小初始化流程：

1. 初始化 I2C。
2. 配置 RESET=GPIO40、INT=GPIO11。
3. RESET拉低10 ms，再拉高并等待50 ms。
4. 使用地址 `0x58` 读取 `0xD0030000` 的50字节信息。
5. 验证芯片类型 `0xCACA220E` 并读取实际分辨率。
6. 按参考驱动发送普通工作模式命令。
7. INT拉低时读取 `0xD0070000` 的触摸报告。
8. 完成读取后必须发送 `D0 00 02 AB` 清除当前报告/中断。

普通工作模式相关命令可从 `hyn_cst66xx.c::cst66xx_set_workmode()` 提取，当前已识别：

```text
D0 00 04 00
D0 00 00 00
D0 00 0C 00
D0 00 01 00
```

移植时应保持发送顺序和参考驱动中的必要延时。

## 4. 下一次工作建议

### 阶段一：最小通信验证

1. 在 I2C BSP 中增加支持4字节寄存器/命令的读写接口。
2. 增加 CST3530 硬件复位。
3. 扫描并确认 `0x58`。
4. 读取信息区并打印芯片类型和分辨率。
5. 暂时不要接入 LVGL。

验收输出至少应包含：

```text
CST3530 found at 0x58
chip type: 0xCACA220E
resolution: <实际X> x <实际Y>
```

### 阶段二：单点触摸读取

1. INT低电平时读取首9字节。
2. 校验报告类型、触点数和帧校验。
3. 解析第一个触点的坐标、ID、事件和压力。
4. 每帧结束发送 `D0 00 02 AB`。
5. 串口测试左上、右上、左下、右下和滑动连续性。

### 阶段三：兼容现有LVGL接口

优先保留：

```c
void touch_Init(void);
uint8_t getTouch(uint16_t *x, uint16_t *y);
```

这样 LVGL 输入层无需大改。底层可内部保存芯片分辨率、最近一次坐标和按下状态。

需要根据屏幕方向验证是否要执行：

- X/Y交换。
- X镜像。
- Y镜像。
- 坐标缩放及边界限制。

## 5. 当前风险和注意事项

- 当前 `touch_bsp.c` 尚不完整，工程大概率会因缺少 `touch_Init()`、`getTouch()` 定义而链接失败。
- `touch_bsp.h` 仍有 FT3168 旧注释。
- CST3530 是4字节命令协议，不能套用原 FT3168 的单字节寄存器读取方式。
- 每帧读取后必须发送ACK，否则可能无法获得下一帧数据。
- 触摸帧最多包含5个项目，缓冲区必须按最大帧长度预留。
- 必须在写入坐标前检查 `x/y` 指针，避免空指针。
- 所有 I2C 操作都应检查 `esp_err_t`，初始化失败时不得继续解析未初始化缓冲区。
- 第一阶段只做普通触摸，不要同时移植固件升级和工厂测试，以降低风险。
